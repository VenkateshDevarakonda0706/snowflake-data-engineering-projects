# Project 10 — Customer Membership History using SCD Type 3 and Type 6

## 1. Project Overview

This project implements **Slowly Changing Dimensions (SCD)** in Snowflake for customer membership changes.

Two approaches are implemented:

- **SCD Type 3** — maintains the current membership and the immediately previous membership in the same customer row.
- **SCD Type 6** — maintains current and previous values together with complete historical versions, effective dates, expiry dates, and a current-record indicator.

The project uses the following customer membership changes:

| Customer | Initial Membership | New Membership | Effective Date |
|---|---|---|---|
| 101 - Amit Sharma | Silver | Gold | 2026-04-01 |
| 103 - Rahul Verma | Silver | Gold | 2026-04-05 |
| 104 - Neha Patel | Gold | Platinum | 2026-04-10 |

# 5. SCD Type 3

## 5.1 What is SCD Type 3?

SCD Type 3 stores the **current value** and the **previous value** in the same row.

For example, before the change:

```text
CURRENT_MEMBERSHIP  = Silver
PREVIOUS_MEMBERSHIP = NULL
```

After Silver changes to Gold:

```text
CURRENT_MEMBERSHIP  = Gold
PREVIOUS_MEMBERSHIP = Silver
```

No new historical row is created.

Therefore, Type 3 maintains only a limited history, normally the immediately previous value.

| Column | Purpose |

| CURRENT_MEMBERSHIP | Current membership |
| PREVIOUS_MEMBERSHIP | Immediately previous membership |
| SEGMENT | Customer segment |

# 9. Tasks 5 and 6 — Apply Type 3 Changes

The Type 3 changes were applied to customers 101, 103, and 104.

The Type 3 rule is:

```text
Old CURRENT_MEMBERSHIP
          ↓
PREVIOUS_MEMBERSHIP

New membership
          ↓
CURRENT_MEMBERSHIP
```

The update was performed in place.

```sql
UPDATE DIM_CUSTOMER_TYPE3 AS T
SET
    PREVIOUS_MEMBERSHIP = T.CURRENT_MEMBERSHIP,
    CURRENT_MEMBERSHIP  = U.MEMBERSHIP,
    CITY                = U.CITY,
    STATE               = U.STATE,
    SEGMENT             = U.SEGMENT
FROM
(
    SELECT
        $1 AS CUSTOMER_ID,
        $2 AS CUSTOMER_NAME,
        $3 AS CITY,
        $4 AS STATE,
        $5 AS MEMBERSHIP,
        $6 AS SEGMENT,
        $7 AS EFFECTIVE_DATE
    FROM @CUSTOMER_STAGE/customers_updates.csv
    (
        FILE_FORMAT => 'CUSTOMER_CSV_FORMAT'
    )
) AS U
WHERE T.CUSTOMER_ID = U.CUSTOMER_ID;
```

The important point is that **no additional row is created** for a changed customer.

# 12. SCD Type 6

## 12.1 What is SCD Type 6?

SCD Type 6 provides a more complete historical solution.

It combines current/previous-value tracking with historical rows.

The Type 6 implementation maintains:

- Current membership
- Previous membership
- Historical membership
- Effective date
- Expiry date
- Current-record indicator

When a customer changes:

1. The old record is expired.
2. A new record is inserted.
3. The old record receives `IS_CURRENT = FALSE`.
4. The new record receives `IS_CURRENT = TRUE`.

---

# 13. Task 9 — Create Type 6 Dimension

The Type 6 dimension was created as:

```sql
CREATE OR REPLACE TABLE DIM_CUSTOMER_TYPE6
(
    CUSTOMER_KEY          NUMBER AUTOINCREMENT,
    CUSTOMER_ID           NUMBER,
    CUSTOMER_NAME         VARCHAR(100),
    CITY                  VARCHAR(100),
    STATE                 VARCHAR(100),
    CURRENT_MEMBERSHIP    VARCHAR(50),
    PREVIOUS_MEMBERSHIP   VARCHAR(50),
    HISTORICAL_MEMBERSHIP VARCHAR(50),
    SEGMENT               VARCHAR(50),
    EFFECTIVE_DATE        DATE,
    EXPIRY_DATE           DATE,
    IS_CURRENT            BOOLEAN
);
```

### Column explanation

| Column | Purpose |
|---|---|
| CUSTOMER_KEY | Surrogate key |
| CUSTOMER_ID | Business key |
| CUSTOMER_NAME | Customer name |
| CITY | Customer city |
| STATE | Customer state |
| CURRENT_MEMBERSHIP | Membership represented by the version |
| PREVIOUS_MEMBERSHIP | Previous membership value |
| HISTORICAL_MEMBERSHIP | Historical membership value for the version |
| SEGMENT | Customer segment |
| EFFECTIVE_DATE | Date from which the version is effective |
| EXPIRY_DATE | Date until which the version is effective |
| IS_CURRENT | Indicates the current version |

# 19. Task 15 — Point-in-Time Historical Query

    EXPIRY_DATE

# 20. Task 16 — SCD Type 3 vs SCD Type 6

| Feature | SCD Type 3 | SCD Type 6 |
|---|---|---|
| Current Value | YES | YES |
| Previous Value | YES | YES |
| Historical Rows | NO | YES |
| Effective Date | NO | YES |
| Expiry Date | NO | YES |
| IS_CURRENT | NO | YES |

## Type 3

```text
One customer
      ↓
One row
      ↓
Current + Previous
```

Type 3 provides limited history.

## Type 6

```text
One customer
      ↓
Multiple versions
      ↓
Current + Previous + Historical
      ↓
Effective Date + Expiry Date + Current Flag
```

Type 6 provides complete historical versions and supports point-in-time queries.
